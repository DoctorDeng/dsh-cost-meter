# Issue #409：账号禁用与费用提示核查

核查时间：2026-10-25 至 2026-10-26（北京时间）。问题由 [@qingyu-ye 在 #409](https://github.com/Han-1413141/dsh-cost-meter/issues/409) 报告，附安装日志、截图及两份会话导出。本文只记录排障所需信息，不复制聊天正文、账号标识或凭据。

## 已确认的情况

报错会话选择的是 **`lobsterai / deepseek-v4-flash`**。10 月 25 日 22:51:08、22:53:15、22:59:28 的三轮记录均为“账号已被禁用”，会话导出中的错误码为 `UNKNOWN`。这是 LobsterAI 渠道的账号拒绝；模型名称包含 DeepSeek，不等于使用 DeepSeek 官方账户。截图中的官方 DeepSeek 余额也不反映 LobsterAI 账号状态。

另一份会话使用 `deepseek-account`，未出现这条禁用错误。两份导出均未提供这次禁用对应的原始 HTTP 状态、平台业务码、请求编号、处罚原因或期限。现有证据将调查范围定位到 LobsterAI 渠道；具体处罚原因仍需平台查询账号记录。

安装日志显示 DSH `0.2.1-rc.3`、Windows、Node `24.21.0`，依赖声明为 `dsh-cost-meter ^1.9.31`、`billion-context ^0.1.206` 和本地包 `dsh-our-free-model-2.7.0.tgz`。前两项是版本范围，不是已安装版本的证明。用户提供的 `dsh-market-log.txt` 与 issue 的一份同名附件哈希相同；日志记载安装和开关事件，两个相关 bundle 为 `ok`，没有封禁诊断。

截图中的“billion-context 计费兼容提醒”解释的是用量记录缺失、费用统计存在偏差。当前费用插件的推理监听器消费原有流并记录 usage；billion-context 接入读取计费记录。本仓库没有 LobsterAI 登录、签到、账号管理或账号禁用接口；官方余额请求固定发往 DeepSeek 官方余额接口。自定义余额请求则由用户配置端点，不能据安装日志推断其实际配置。

## 按 2.7.0 标签核对的后台行为

这里核对的是上游公开源码标签 `v2.7.0`（提交 `119c5bfe869a5dd8c24439d68f7ad415462c7758`），不是报障者本地压缩包的逐字节内容。

- [自动签到](https://github.com/Ebony-Vinyl/dsh-our-free-model/blob/v2.7.0/vendor/channel-pack/src/auto-checkin.ts)：默认开启，启动后默认延迟 30 秒，遍历有账号的渠道。成功记录当天状态后避免当天重复；没有任何成功处理证据时不记当天完成，下一次启动还会尝试。排除表只列出 zcode。
- [LobsterAI 积分实现](https://github.com/Ebony-Vinyl/dsh-our-free-model/blob/v2.7.0/vendor/channel-pack/src/lobsterai-credits.ts)：包含活动查询、签到 POST 和账户余额查询，属于带账号身份的网络活动。
- [凭据调度](https://github.com/Ebony-Vinyl/dsh-our-free-model/blob/v2.7.0/vendor/channel-pack/src/index.ts)：有启动检查及每 30 分钟的续期检查；这是检查周期，不是每个账号都会每 30 分钟发出续期请求。
- [模型目录](https://github.com/Ebony-Vinyl/dsh-our-free-model/blob/v2.7.0/vendor/channel-pack/src/lobsterai-adapter.ts)：该适配器成功获取后复用目录，[失败或空结果默认等待 30 秒](https://github.com/Ebony-Vinyl/dsh-our-free-model/blob/v2.7.0/vendor/channel-pack/src/remote-catalog-gate.ts)。不能把 #2936 所述的 5 分钟周期直接算成本次附件的请求量。
- 同一适配器区分认证、限流、额度和服务错误，并含账号池处理逻辑。会话导出的 `UNKNOWN` 缺少原始状态，无法还原这次实际走过哪个错误分支；注册了账号池也不说明报障者配置了多个账号。

## 原因判断及处理顺序

| 排查方向 | 证据与判断 | 应采取的措施 |
| --- | --- | --- |
| 第三方接入复用登录凭据 | 多处相近报告具有这个共同特征，是优先排查方向；尚无官方处罚归因。 | 已禁用账号停止第三方后台访问，向平台核对授权的接入方式与账号状态。 |
| 自动签到、重启后的再次尝试 | 对应版本源码存在；社区有人报告未聊天也被封。 | 关闭该渠道自动签到；上游应对已禁用账号停止自动任务，避免失败随重启反复执行。 |
| 目录、余额及续期请求频率 | 多种后台请求存在，但附件没有请求次数或限流响应。 | 按账号合并并发、缓存成功结果、失败等待，遵守 `Retry-After`；记录脱敏的状态码和时间。 |
| 多账号、共享账号、多个终端同时使用 | 社区有此类使用描述，官方协议有相关限制；附件没有证明报障者这样使用。 | 遵守账号和终端限制，检查是否有遗留进程同时访问同一账号。 |
| 积分不足、凭据过期、模型权限 | 都可能造成拒绝，但其含义与明确的账号禁用不同。 | 获取原始 HTTP 状态及业务码，分别处理余额、重新认证和权限；不要只靠 `UNKNOWN` 分类。 |
| 网络出口、设备变化、请求内容 | 附件未提供平台风控理由或相关事件。 | 保留为平台核查项，不凭猜测修改设备标识、网络配置或聊天内容。 |
| 费用统计误差提示 | 提示由本地用量覆盖状态产生，没有账号管理动作。 | 调整提示的位置和文字；不能把隐藏提示视为解除账号禁用。 |

下一步最有用的证据是平台确认的账号状态、处罚原因和期限，以及同一失败请求的脱敏 HTTP 状态、业务码和 request ID。通过官方支持渠道核对一次账号状态即可；不要连续重试已禁用账号，也不要用新账号轮换来验证封禁规则。

## 本次在费用插件中的修改

1. 移除自动弹窗及其开关，在“设置 → 费用 → 概览”显示普通灰字：“billion-context 部分用量记录不完整，费用统计可能存在偏差。”用量正常后隐藏。保留旧配置字段以兼容现有账本。
2. 官方余额和通用 HTTP 自定义余额收到 401/403 后，自动查询等待配置的刷新间隔；错误仍显示，手动刷新可在修正认证后重试。
3. 这两类余额收到 429 后，自动查询和手动刷新均等待，取配置间隔与服务端 `Retry-After` 中较晚的时间；支持秒数及 HTTP 日期，缺失或无效时使用配置间隔。在途请求后的排队刷新同样受限。
4. 成功后清除等待状态；替换凭据或自定义查询来源时作废旧缓存。其他临时错误保留原有恢复方式，不读取或展示上游错误正文。

这些等待状态属于当前插件进程，未扩展到其他插件的签到、推理或认证逻辑。本次修复降低本仓库重复查询的风险，不声称已解决 LobsterAI 账号禁用。验证使用本地模拟响应和浏览器测试，没有用真实账号试探封禁规则。
