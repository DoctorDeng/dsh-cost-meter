## v1.7.33 — JSON bodies for custom balance POST requests

### English

Resolves #165: the backend already accepted request bodies, but the settings UI had no body editor. In **Settings → Cost → Quota**, expand a custom provider balance, select **POST**, and enter **Request body (JSON)**.

For an endpoint that accepts `{"account_id":"example-account"}` and returns `{"data":{"balance":12.5}}`, enter that JSON body and set the extract rules to `{"remaining":"data.balance"}`.

- Valid JSON is saved per entry and sent as entered, preserving nested values, JSON strings and large integer IDs. Invalid JSON keeps the last valid configuration; clearing the editor removes the body.
- GET/HEAD omit the body while preserving its configuration for POST. Existing object and raw-string bodies remain supported.
- `Content-Type` defaults to `application/json` and respects an explicit header regardless of capitalization.
- Settings persist through RPC and restarts. Bodies are ordinary saved configuration; credential placeholders remain a request-header feature.

### 中文

解决 #165：后端原本支持请求体，但设置页缺少入口。进入**设置 → 费用 → 额度**，展开自定义余额，选择 **POST**，即可填写**请求体 (JSON)**。

例如请求体为 `{"account_id":"example-account"}`，接口返回 `{"data":{"balance":12.5}}`，解析规则填写 `{"remaining":"data.balance"}`。

- 有效 JSON 按原文保存并发送，保留嵌套值、JSON 字符串和大整数 ID；格式错误保留上次有效配置，清空则移除请求体。
- GET/HEAD 不发送请求体，切回 POST 保留配置；兼容已有对象和原始字符串。
- 默认使用 `Content-Type: application/json`，自定义请求头不区分大小写。
- 每条配置独立保存，支持 RPC 与重启。请求体属于普通配置，凭据占位符仍只用于请求头。

### Upgrade / 升级

```sh
dsh plugin --profile web add dsh-cost-meter@1.7.33
```

Restart DSH and refresh the browser. / 升级后重启 DSH，并刷新浏览器。
